🎯 正确的架构模式

Pipeline 模式

DataAnalysisAgent

为什么用 Pipeline？

  • 固定流程：fetch → process → merge
  • 步骤确定，顺序不变
  • 不需要动态决策
async def run(trigger_time):
    # 1. 获取数据
    data = await fetch_data()

    # 2. 处理批次
    batches = await process_batches()

    # 3. 合并结果
    summary = await merge_results()

    return save(summary)

优势：

  • ✅ 470 行（原 658 行，减少 29%）
  • ✅ 逻辑清晰，一目了然
  • ✅ 不继承框架基类
  • ✅ 纯函数组合
Agent Loop 模式

ResearchAgent

为什么用 Loop？

  • 动态决策：每步根据上下文选择工具
  • 循环执行：不知道要几步
  • ReAct 模式：Reasoning + Acting
async def run(input_data):
    await initialize(input_data)

    # ReAct 循环
    while not should_terminate():
        # 1. Think: 选择工具
        tool = await select_tool()

        # 2. Act: 执行工具
        result = await execute_tool(tool)

        iteration += 1

    return await finalize()

优势：

  • ✅ 450 行（原 474 行，减少 5%）
  • ✅ 显式循环，易于理解
  • ✅ 保留所有 ReAct 功能
  • ✅ 去除 LangGraph 复杂性

💡 核心教训

✅ 正确的技术选型原则

1. 理解问题本质

  • Loop 型：动态决策、不确定步数 → Agent Loop Pattern
  • Pipeline 型：固定流程、确定步骤 → 异步函数组合
  • Orchestration 型：协调多个组件 → asyncio.gather

2. 选择最简单的方案

能用函数 → 就不用类
能用类   → 就不用框架
能用框架 → 选最轻量的

❌ 避免的错误

  • ❌ 强行让所有 Agent 继承同一个基类
  • ❌ 把 Pipeline 塞进 Loop 框架
  • ❌ 为了用框架而用框架

✅ 正确做法

  • ✅ Loop 归 Loop，Pipeline 归 Pipeline
  • ✅ 根据问题选择方案，不是根据框架
  • ✅ 保持简单，避免过度抽象
